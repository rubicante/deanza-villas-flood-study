# Alluvial Fan Flood Study

Terrain-driven flood risk analysis pipeline for alluvial fan parcels in Borrego Springs, CA.
Given a parcel polygon, the pipeline derives the contributing area, computes D8 and D∞ flow
accumulation, extracts the stream network, and produces an interactive stream morphology explorer.

---

## How it works

```
parcel polygon
    → contributing area (10m DEM BFS upstream)
    → 1m + 10m DEM fetch (USGS TNM, clipped to CA)
    → DEM conditioning (breach + fill)
    → flow direction + accumulation (D8 and D∞)
    → stream extraction
    → binary export → stream explorer (outputs/maps/index.html)
```

All elevation data comes from USGS The National Map (no API key required).
All parcel data comes from SANDAG Parcels_East and OpenStreetMap (no API key required).

---

## Quickstart

```bash
# Activate the project virtualenv
source .venv/bin/activate

# Full pipeline (fetches parcel, DEM, computes everything)
python -m deliverable._pipeline all

# Or step by step
python -m deliverable._pipeline prepare        # contributing area
python -m deliverable._pipeline dinf1m         # D∞ 1m streams
python -m deliverable._pipeline dinf10m        # D∞ 10m streams
python -m deliverable._pipeline d81m           # D8 1m streams
python -m deliverable._pipeline d810m          # D8 10m streams

# Switch parcels without touching code
python -m deliverable._pipeline all --parcel deanza_villas
python -m deliverable._pipeline all --parcel country_club   # default

# Housekeeping
python -m deliverable._pipeline clean          # delete derived artifacts
python -m deliverable._pipeline clean-all      # also delete DEM tile cache
```

Open `outputs/maps/index.html` in a browser to explore results.

## Active parcel

Select the parcel at runtime with `--parcel`. Parcel generators live in
`deliverable/parcels.py`; the registry mapping names to generators is in
`_pipeline.py`. Currently available:

| Key | Description |
|---|---|
| `country_club` | De Anza Country Club (OSM way 44500984) — **default** |
| `deanza_villas` | De Anza Villas residential complex (SANDAG parcels) |

To add a new parcel: implement a generator in `parcels.py` and add an entry to
`_PARCELS` in `_pipeline.py`. Then `clean` and re-run with `--parcel <key>`.

## Repository layout

```
deliverable/          Portable hydrology library + project pipeline CLI
  _pipeline.py        Main CLI (prepare / build / clean)
  parcels.py          Parcel boundary generators
  fetch.py            USGS TNM DEM fetch (1m + 10m)
  preprocess.py       DEM conditioning (breach + fill)
  d8.py / dinf.py     Flow direction + accumulation
  streams.py          Stream extraction
  reachability.py     Optional reachability filter
  upstream.py         Contributing area BFS
  verify.py           Accumulation sanity checks

scripts/              One-off data acquisition scripts
  fetch_parcel_deanza_villas.py
  fetch_parcel_deanza_country_club.py
  fetch_fema.py       FEMA NFHL flood zones
  fetch_huc12.py      HUC-12 watershed boundary

data/raw/vectors/     Source vector inputs (fetched on demand, not committed)
data/raw/dem/tiles/   Cached DEM tiles (not committed)
data/derived/         Computed rasters and vectors (deleted by clean)
outputs/maps/         Stream explorer + GeoJSON/binary assets
```

## Context layers (outputs/maps/)

The stream explorer overlays several reference layers alongside the stream network:

| Layer | Source | File |
|---|---|---|
| Contributing area | Computed by pipeline | `parcel_contributing_area.geojson` |
| Parcel boundary | Generated by parcel script | `parcel_boundary.geojson` |
| FEMA NFHL flood zones | `scripts/fetch_fema.py` | `nfhl_borrego_valley.geojson` |
| HUC-12 watershed | `scripts/fetch_huc12.py` | `borrego_palm_canyon_huc12.geojson` |
| DRI 2015 fan zones | Committed reference layer | `dri_2015_fan_zones.geojson` |
